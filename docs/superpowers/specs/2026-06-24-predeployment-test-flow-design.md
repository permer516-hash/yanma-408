# 部署前测试流程设计

## 目标

为研码 408 建立一套本地和 CI 均可重复执行的部署前测试流程，验证前后端能够启动、关键接口可用、核心用户流程可走通。测试改动仅限测试配置、测试数据和测试代码，不重写业务逻辑。

## 当前基础

- 后端使用 Spring Boot 3.4、Maven、JUnit 5 和 H2，已有少量上下文与服务单元测试。
- 前端使用 Next.js 16、TypeScript、ESLint 和 `@playwright/test`，已有登录与部分页面的 E2E 草稿。
- 现有 Playwright 测试依赖本机 PostgreSQL 演示数据和固定账号，缺少统一服务编排，无法稳定作为部署门禁。

## 测试分层

### 后端测试

继续使用 Maven 测试生命周期。保留现有单元测试，并增加使用 `test` profile 与 H2 的集成测试，至少验证：

- Spring 应用上下文能够启动。
- `/api/health` 返回健康状态。
- E2E 所依赖的认证和题库基础接口能够返回确定性结果。

后端测试不得依赖 Docker、PostgreSQL、Redis 或 MinIO。

### E2E 专用运行模式

增加仅由 `e2e` profile 启用的后端配置：

- 使用独立 H2 内存数据库。
- 禁用外部基础设施依赖或改用本地无副作用配置。
- 通过仅在 `e2e` profile 生效的测试数据初始化器创建固定账号与最小题库数据。
- 测试数据仅覆盖 E2E 所需角色和页面，不复制生产数据集。

该 profile 不被默认开发、测试或生产配置引用。

### Playwright 轻量流程

Playwright 配置统一编排后端和前端服务，使用固定端口和可配置的 `E2E_BASE_URL`。测试按角色和风险拆分：

1. 服务冒烟：前端首页和后端健康检查可访问。
2. 学生流程：登录、进入仪表盘、浏览题库、筛选题目、打开题目详情、查看章节练习。
3. 权限边界：学生不显示管理入口，管理员能够进入题库管理。

E2E 只验证关键可见结果和导航，不遍历全部题目，不依赖执行顺序，不修改共享环境数据。

## 命令与门禁

前端增加清晰脚本：

- `npm run typecheck`：TypeScript 类型检查。
- `npm run test:e2e`：运行轻量 Playwright 流程。

仓库增加统一部署前脚本，依次执行：

1. `mvn test`
2. 前端依赖检查、ESLint、TypeScript 检查和生产构建
3. Playwright E2E

任一步失败即以非零状态结束。README 记录首次安装浏览器、单独运行各层测试和完整门禁命令。

## 失败诊断与产物

- Playwright 仅在失败时保留截图、trace 和错误上下文。
- 服务启动使用健康检查等待，不使用固定长时间 sleep。
- 测试失败时保留前后端日志位置，便于区分启动失败、接口失败和 UI 断言失败。

## 范围外事项

- 不引入完整视觉回归测试。
- 不做压力测试、全量题库遍历或生产数据库迁移演练。
- 不修改认证、题库、练习等业务实现来迎合测试。
- 不把 E2E mock 或测试账号初始化逻辑打入非 E2E 环境。

## 验收标准

- 全新测试进程无需现有 PostgreSQL 数据即可启动前后端。
- 后端测试、前端静态检查与构建均通过。
- Playwright 核心流程稳定通过，并且失败时产物可定位问题。
- README 提供单层测试和部署前完整测试的准确命令。
